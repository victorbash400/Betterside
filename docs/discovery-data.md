# Discovery map precision and outage recovery

Heatmap and Areas are separate visualizations. Heatmap renders smooth, weighted kernels at provider-reported event localities. Approximate localities retain source uncertainty. Country-only reports remain visible as small, outlined country-centre markers and do not enter the heat-density calculation. Areas renders reporting polygons and event-location symbols, with heat layers disabled. There is no invented geographic scattering or conversion of regional totals into incident coordinates. Source scope and reference periods remain in selected details and layer settings. The map starts with no causes selected. Sandbox catalogue projects are disabled by default and can be enabled explicitly in Data sources.

OCHA HAPI conflict summaries are monthly aggregates, including districts where supplied, rather than incident-level ACLED coordinates. Reference: https://hdx-hapi.readthedocs.io/en/latest/data_usage_guides/coordination_and_context/ . MapLibre heatmaps use point data: https://maplibre.org/maplibre-style-spec/layers/#heatmap . District boundaries use the existing official p-code geometry, without converting reported totals into precise events.

The live validation on 2026-10-29 returned 14,663 records, including 1,673 located observations and 137 Ukrainian district conflict summaries. One provider continued to time out. Counts can vary with availability and source updates. The approximately 14.8 MB JSON response compressed losslessly to approximately 0.9 MB; large responses now negotiate gzip and retain encoding-specific ETags.

Successful per-source results may be retained for seven days after freshness expiry if refresh fails. Their original dates are preserved and the status becomes Cached, never Available. Error cooldowns and ordinary source TTLs still apply. Browser IndexedDB holds one validated public discovery snapshot, restoring it before requests complete. Per-source failures merge with saved records without duplicating them; a successful empty result replaces old records. The browser discards saved records older than seven days. An unavailable provider no longer reports a misleading successful count of zero.

Initial and manual loads make one request. Connectivity and focus events can attempt recovery when failed-source cooldowns allow. No delayed retry timers or polling are used.

Validation covers aggregate-versus-event geometry, all three default cause selections, signed rainfall deficits, zero versus missing values, sandbox exclusion, cache retention and expiry, original timestamps, per-source browser merges, successful empty responses, and gzip/ETag round trips. On 30 October 2026 the live snapshot contained 14,669 records; the three default causes produced 276 weighted reporting anchors. Heatmap retains those anchors and their original precision metadata; Areas uses only available matching polygons. Three aggregate locations lacked matching boundaries. GDACS timed out and remained an error. Counts and provider availability can change. No server was started or restarted.

## Workspace chat tools

Chat renders structured tool outputs as inline grids, calculations, save confirmations and sandbox payment cards. Search defaults to the full available source catalogue; `scope: selection` explicitly limits research to visible record IDs. An empty cause selection still draws no layers and does not mean the source catalogue is empty. Map filters and organization focus use the same client state as the manual controls.

`save_records` resolves IDs against server catalogue/discovery records and this visitor's saved records, validates a single tracking snapshot, and waits for revision-checked persistence before returning success. Restoring conversation history does not replay workspace mutations. Calculations use structured operations, never evaluated code; USD splits preserve cents.

`prepare_payment` supports existing BetterSide Sandbox projects only. It creates a real sandbox order through the same service as manual checkout, with a validated PayPal approval URL. The user approves in PayPal; chat has no capture tool. Inline cards read donor-scoped ledger status on mount, window focus, or an explicit check, without polling. `list_contributions` reads this visitor's recorded order states and renders a grid; prepared orders are not completed contributions. Public organizations retain their own verified external donation URLs.

Agent construction and grounding instructions live in `app/agents/`. Individual tool definitions live in `app/tools/`; its index assembles the available tools. The chat API route validates and loads request context, invokes the agent, and streams the response. Inline card layouts are application components populated by structured tool results, not scripted answers.


## Conflict events and organization directory additions (2026-10-31)

UCDP Candidate Events 26.0.9 supplies 2,014 preliminary September 2026 organized-violence event records. 1,017 are reported at locality level and 470 within approximately 25 km of a locality. District- and province-level codes retain their provider-supplied regional anchors, labelled administrative areas. Country-only or unspecified positions use country-centre placeholders when country geography is available. Every record retains its period, source precision code, source release URL and snapshot retrieval date. These are monthly candidate data, not a live battlefield feed. State-based, non-state and one-sided violence are identified in event details. Incident counts and fatality estimates have separate metric types.

The current source contains 13 internally inconsistent fatality estimate ranges. Those events are retained, with explicit source alerts; their fatality measures are withheld. No estimates are corrected or invented. Event kernels use a separate normalization from national summaries, and unlocated events are never merged into HAPI totals. Records from different providers can overlap and must not be added as distinct crises without a shared provider identity.

Refresh the public candidate snapshot with `python3 scripts/snapshot-ucdp.py`. The script discovers monthly CSV links from UCDP's official download index and uses the standard CSV parser. It fails on changed fields or oversized responses. The app consumes the versioned snapshot; the refresh button does not invent a newer release. Source: https://ucdp.uu.se/downloads/ . Precision methodology: https://ucdp.uu.se/downloads/candidateged/ucdp-candidate-codebook.pdf .

The adapter does not infer activities, causes, beneficiaries, payment recipients or donation URLs from a directory entry.
